# Migration Runner Contract

This document defines the app-side contract expected by the Underlay migration
framework scripts.

The Underlay scripts and `underlay-devtools` handle:

1. digest-pinned bundle preparation and replay input
2. bundle publish/pull flow
3. governance, integrity, recovery, verify, audit, and drift report commands
4. evidence, promotion, and CI guard automation

The consuming app still owns the actual migration runner.

## 1. Runner Responsibility Boundary

Your app migration runner must:

1. read deterministic replay input prepared by `underlay-devtools migration run`
2. execute the real migration pipeline for the consuming app
3. write the core migration artifacts expected by the framework scripts

It must not assume mutable OCI tags, implicit local state, or ad hoc artifact
locations.

## 2. Invocation Contract

When `APP_MIGRATION_RUNNER_CMD` is configured, the sample scripts invoke it after
`underlay-devtools migration run`.

The command is executed via:

```bash
zsh -lc "$APP_MIGRATION_RUNNER_CMD"
```

The following environment variables are provided:

1. `BUNDLE_REF`
   - digest-pinned bundle ref used for the run
2. `OUTPUT_DIR`
   - directory where run artifacts should be written
3. `RUN_REPORT`
   - exact expected path for `run-report.json`
4. `DECISION_INDEX_FILE`
   - exact expected path for `decision_index.json`
5. `DECISION_JOURNAL_FILE`
   - exact expected path for `decision_journal.ndjson`
6. `REUSE_FROM_DIGEST_REF`
   - provided for refresh runs when configured

Recommendation:

1. Treat these variables as authoritative output paths.
2. Do not hard-code alternate paths inside the app runner when these values are
   present.

## 3. Required Output Artifacts

The app runner must write these files before the sample script chain can
continue:

1. `run-report.json`
2. `decision_index.json`
3. `decision_journal.ndjson`

The sample scripts now fail fast if any of these are missing after runner
execution.

The standard verification and audit artifacts are generated by the Underlay
report suite after the runner completes, so the app runner does not need to
pre-generate those JSON files itself.

## 4. `run-report.json` Contract

`run-report.json` should serialize the full `PipelineRunReport` shape from
`underlay-migration-core`.

At minimum the framework expects:

1. top-level `run_id`
2. top-level `started_at`
3. top-level `finished_at`
4. `extract.batch_count`
5. `extract.record_count`
6. `normalize.batch_count`
7. `normalize.record_count`
8. `transform.batch_count`
9. `transform.record_count`
10. `decide.decision_count`
11. `decide.unresolved_count`
12. `decide.reused_count`
13. `decide.resolved_count`
14. `decide.invalidated_count`
15. `decide.invalidations`
16. `decide.unresolved_queue`
17. `decide.governance_issues`
18. `integrity_gate`
19. `materialize.inserted`
20. `materialize.updated`
21. `materialize.skipped`
22. `assets.resolved_count`
23. `assets.unresolved_count`
24. `verify.passed`
25. `verify.checks`
26. `verify.issues`
27. `resume_diagnostics`

For refresh runs, the `decide` section is the primary source for:

1. decision reuse summary generation
2. AI suppression KPI calculation
3. invalidation counting
4. drift threshold inputs

If the app emits placeholder values here, refresh evidence will be misleading.

## 5. `decision_index.json` Contract

`decision_index.json` must conform to the `DecisionIndex` contract from
`underlay-migration-core`.

It should:

1. be built from the decision journal written by the same run or a compatible
   merged baseline
2. preserve fingerprint lookup compatibility for refresh passes
3. remain deterministic for identical input and merge ordering

This artifact is used for:

1. lineage-aware drift checks
2. refresh reuse analysis
3. promotion evidence

## 6. `decision_journal.ndjson` Contract

`decision_journal.ndjson` must be append-only NDJSON where each line is a valid
`DecisionJournalRecord`.

It must preserve:

1. `decision_id`
2. `fingerprint`
3. `decision_type`
4. `outcome`
5. `confidence`
6. `resolver_version`
7. `prompt_version`
8. `target_schema_version`
9. `created_at`
10. `provenance`

Never rewrite historical journal lines during refresh or rerun flows.

## 7. Recommended Runner Flow

The consuming app runner should follow this pattern:

1. load replay input prepared by `underlay-devtools migration run`
2. execute `extract -> normalize -> transform -> decide -> materialize -> assets -> verify`
3. serialize `PipelineRunReport` to `RUN_REPORT`
4. serialize decision journal to `DECISION_JOURNAL_FILE`
5. build and serialize decision index to `DECISION_INDEX_FILE`
6. exit non-zero on blocking migration failure

## 8. Script Behavior After Runner Completion

Once the required runner artifacts exist, the sample scripts handle:

1. governance report
2. integrity report
3. recovery report
4. verify artifact generation
5. audit artifact generation
6. optional governance policy report
7. refresh drift report for refresh passes

This split keeps the app-side runner focused on migration execution while
letting Underlay own the generic gate/report/evidence flow.
