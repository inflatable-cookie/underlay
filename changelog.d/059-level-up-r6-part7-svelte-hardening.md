### Fixed

- `ForgotPasswordFlow`: every step handler (`request code`, `verify code`, `reset password`, `resend code`) now guards state writes with an `onDestroy` disposal flag, so unmounting mid-request never advances the step or leaves loading stuck. Requesting a code no longer silently advances to the verify step on a real outage: network failures (`status: 0`), `429`, `5xx`, and unclassifiable errors surface a fixed "couldn't send a reset code" message, while expected 4xx responses (including `404` for unknown accounts) still advance so the flow cannot be used to enumerate accounts.
- `AdminUserMenu`: a rejected `onLogout()` no longer closes the dialog through an unhandled rejection — the failure stays visible in the dialog with a retry, disposal is guarded, `accountHref` is sanitized through `resolveRedirectTo` (falling back to `/account`), and the avatar gradient defaults to `var(--underlay-admin-nav-badge-overview, …)` instead of a hardcoded hex gradient.
- `EntityRelationField`: the hidden input no longer carries a `required` attribute HTML ignores, and `Field`'s `id`/`describedBy` (plus an echoed invalid `validationState`) are wired to the relation control group so the label and error text are associated with the control.
- `EntityListCard`: replaced the `const PoodleListCard: any = ListCard` cast and the four copy-pasted `ListCard` branches with a single typed `<ListCard>` invocation whose `leading` / `badges` / `footer` snippets are conditional.
- `AdminDashboardPage`: back-button info now reuses `useTemplateBackInfo` and renders the caller's `backHref` as the SSR/first-paint fallback instead of `null`, so the back link does not appear only after mount. Configured sections are rendered with stable `{#each}` keys.
- `AdminNavList`: both navigation loops use stable keys.
- `UserForm`: cancel now navigates through `navigateBack` with a `resolveRedirectTo`-sanitized target (unsafe hrefs fall back to context/parent navigation) instead of the legacy `navigateOnCancel` `location` assignment, and email validation rejects `@`, `a@`, `@b`, whitespace, empty domain labels, and dotless domains instead of only checking for `@`.
- `MediaEditor` / `NightfireMediaContext`: added the optional `resolveMedia(id)` context hook and hydrate a reopened block's `media_id` into its title, thumbnail, and kind with disposal and stale-id guards (best-effort, never rewriting the block); the `Remove` button is disabled while a pick is in flight.
