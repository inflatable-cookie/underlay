Moved password and email OTP hashing and verification onto Tokio's blocking pool. New passwords require Good strength, and new TOTP backup codes use 16 symbols for 80 bits of entropy. Existing backup codes continue to verify. Auth extractors include retry timing in 429 responses, JWT constructors clamp non-positive lifetimes to one unit, and super-role assignment requires the super role even in custom hierarchies. Session refresh checks version arithmetic, and Google OAuth keeps HTTP timeouts and logs provider failure status.

Breaking for Rust auth adapters. Implement `EmailTotpCodeRepository::mark_code_used` as a single conditional update on the active, unused, unexpired code ID and return whether the update succeeded. Implement `GoogleOAuthCredentialRepository::find_google_credential_by_subject` for Google credentials and enforce uniqueness of the Google subject as well as one Google credential per user. Google sign-in resolves existing links by subject before looking up the email.

Applications that destructure an auth extractor rejection must account for the new header map. Run the async password and email OTP services on a Tokio runtime. Custom password hashers and verifiers used by the async service must have a `'static` lifetime. Allow the longer, hyphenated backup codes in any consumer input or display with a fixed length.
